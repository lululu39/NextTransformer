# H-only Chord with one position step and one velocity mixing coefficient

This screen removes both direction splits. Attention and the MLP still preview h + μv. One softplus α updates the whole position. A single sigmoid β combines the old velocity with the realized displacement at complementary weights before projection onto the new tangent plane. The [model](../../nexttransformer/methods/chordres_honly_single_step/) has a D-to-3 token projection, or D-to-2 at the terminal MLP.

The original static one-beta model and static three-gain model both used two position steps. At matched high control LR, seed and initialization, three gains improved all 12 recorded validations from 250 to 3,000 by an average 0.00162 BPB (at 2,000: 0.812241 versus 0.813652). This experiment measures whether the simpler velocity and position geometry works when the controls are token-dependent. It keeps the native mHC auxiliary AdamW peak LR 0.000848528137423857, 23 layers, width 1,536, FFN 6,144, seed 42 and native zero-initialized attention and MLP output projections, ClimbMix, eight H100 ranks with B8 and eight accumulation steps, 2,048 context and saved BF16 forces. The model has 210,432 gate weights and 137 control biases. Eight-rank admission uses the fixed dense FLOPs anchor. Training retains the 46,875-update LR schedule.

Evaluate BPB every 250 updates on 41,943,040 validation tokens. Before 2,000, two consecutive deficits against the best historical Chord at those same updates stop the experiment if the deficit persists or widens. At 2,000, a win against the best previous Chord (0.812241) promotes the existing run directly to 8,000. That threshold is already within 0.00193 BPB of official mHC (0.810313) and 0.00158 of Block AttnRes (0.810662). A failing screen saves a complete checkpoint at the decision update. Preserve the gradient failure guard and per-GPU lease handoff.

The matched-normal variant passed preflight but hit a duplicate W&B configuration key before its first formal training update (run `23153c4c`). The active zero-init variant uses [the native-init launcher](../../launch/train_chord_zero_init.py). Token embeddings and other ordinary weights use the upstream initialization. At zero force, position-step or velocity-retention gradients can start at zero. The CUDA oracle tests nonzero forces and the full-model preflight checks the initial logits against the native static Chord.
